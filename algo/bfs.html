BFS と DFS

グラフやグリッドを「つながっている順に全部見る」のが探索です。BFS (幅優先) はキューで近い順に広げるので、辺の重みが全部 1 なら最短距離がそのまま出ます。DFS (深さ優先) は行けるところまで潜るので、連結成分や木の処理、閉路検出に向きます。

考え方

BFS の不変条件　キューの中には「距離 d のもの」と「距離 d+1 のもの」しか入っていない。だから取り出した順が距離順になり、初めて到達したときの距離が最短。到達済みの判定は「dist が −1 でない」で行う。
  • グリッドは (行, 列) をそのまま頂点にする。4 方向は dx = {1,0,−1,0}, dy = {0,1,0,−1}。
  • グラフは隣接リスト vector<vector<int>> G(N) で持つ。
  • DFS は再帰で書くのが楽だが、Python は深さ 10^5 で落ちるので、スタックで書くか再帰上限を上げる。
  • 「01-BFS」: 辺の重みが 0 か 1 だけなら、deque の先頭 / 末尾に入れ分けて BFS と同じ計算量で最短路。

動かして見る

S から各マスまでの最短距離を BFS で求めます。灰色は壁。黄色がキューに入っているマス、水色は距離が確定したマスです。

実装

計算量とハマりどころ

  • O(V + E)。グリッドなら O(HW)。
  • 訪問済みチェックは「キューに入れるとき」に行う。取り出すときにすると同じ頂点が何度も入って遅くなる。
  • 範囲外チェックを壁チェックより先に (添字エラー)。
  • C++ の再帰 DFS は深さ 10^5 程度なら大抵大丈夫だが、10^6 はスタックが不安。
  • 「状態」を頂点にする発想: (位置, 持ち物の有無) や (位置, 残り回数) を 1 つの頂点として BFS すると、条件付きの最短路が解ける。

典型問題のパターン

  • 迷路の最短手数、到達できるマスの個数
  • グラフの連結成分の数、二部グラフ判定 (BFS で色を交互に塗る)
  • 木の各頂点の深さ・親 (根から DFS / BFS)
  • 「特定のマスを通らずに行けるか」「壁を 1 回だけ壊してよい」(状態を増やす BFS)
  • 幅優先で「最短経路の復元」(親を記録して逆順にたどる)
