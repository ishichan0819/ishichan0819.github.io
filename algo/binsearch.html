二分探索

「ここより左は全部 NG、右は全部 OK」という単調な境界があれば、範囲を毎回半分にして log N 回で境界を見つけられます。配列の中の値を探すだけでなく、「答えを決め打ちして判定する」使い方 (答えで二分探索) が水色以上では必須です。

考え方

めぐる式　ng は「絶対に条件を満たさない側」、ok は「満たす側」の添字を持つ。|ok − ng| > 1 の間、真ん中 mid を判定して ok か ng を更新。終わったとき ok が境界。初期値を範囲の「外側」に置くので、境界が端にあっても壊れません。
  • lower_bound: 「x 以上の最初の位置」= 判定 A[mid] ≥ x が ok。
  • 答えで二分探索: 「答えが X 以下で達成できるか?」が判定できて単調なら、X を二分探索する。判定 1 回が O(N) でも全体 O(N log X)。
  • 実数の二分探索は「100 回回す」で十分 (2^-100 まで縮む)。

動かして見る

ソート済みの配列から「x 以上になる最初の位置」(lower_bound) を探します。

実装

計算量とハマりどころ

  • O(log N)。N = 10^18 でも 60 回。判定関数の重さがそのまま効く。
  • 単調性の確認が最重要。判定結果が NG NG NG OK OK のように 1 回だけ切り替わることを言葉で確かめる。
  • while (ng < ok) や mid ± 1 で書くと境界を間違えやすい。めぐる式に固定する。
  • 「以上 / より大きい」を取り違えない。個数を数えるときは upper_bound − lower_bound。
  • C++ で (ok + ng) / 2 は負数側で切り捨て方向が変わる。ng + (ok − ng) / 2 か、ng ≥ −1 を保証する。

典型問題のパターン

  • ソート済み配列で「x 以下の要素の個数」「x に最も近い値」
  • 2 つの配列から a + b ≤ K となる組の個数 (片方をソートして二分探索)
  • 「最小値の最大化」「最大値の最小化」: 例 “どの区間の長さも X 以下に分割するのに必要な回数が K 以下か” → X を二分探索
  • 半分全列挙: N ≤ 40 の部分和問題を 2^20 + 2^20 に分けて二分探索
