全探索と bit 全探索

競プロの出発点は「全部試す」です。ただし全部試すには、漏れなく・重複なく・制限時間内に列挙する書き方が要ります。N 個の要素それぞれを「選ぶ / 選ばない」で分ける 2^N 通りは、0 から 2^N−1 までの整数 1 つで表せます。これが bit 全探索です。

考え方

選び方 = 整数　整数 s の下から i 番目のビットが 1 なら「i 番目を選ぶ」。s を 0 から 2^N−1 まで回すだけで、すべての部分集合を 1 回ずつ通ります。判定は (s >> i) & 1。
  • N ≤ 20 なら 2^20 ≈ 10^6 通り。各通りの処理が O(N) でも 2×10^7 で余裕です。N ≤ 25 くらいまでが限界。
  • 「選ぶ / 選ばない」以外の分岐 (例: 3 通り) は 3 進数で同じことができます。
  • 順列の全探索は next_permutation (C++) / itertools.permutations (Python)。N ≤ 10 が目安 (10! ≈ 3.6×10^6)。

動かして見る

A = [3, 5, 7, 9] から、和がちょうど 12 になる選び方をすべて見つけます。

実装

計算量とハマりどころ

方法計算量N の目安
bit 全探索O(2^N · N)N ≤ 20〜22
順列全探索O(N! · N)N ≤ 10
2 重ループO(N^2)N ≤ 5000
  • 1 << N は N ≥ 31 でオーバーフロー。C++ で N が大きいときは 1LL << N。
  • 和の途中で int を超えることが多い。C++ では long long を最初から使う。
  • 「制約が小さい」は全探索のサイン。N ≤ 20 を見たらまず bit 全探索を疑う。
  • 半分全列挙: N ≤ 40 なら前半と後半を 2^20 ずつ列挙して二分探索で合わせる (次のページ)。

典型問題のパターン

  • N 個の中からいくつか選んで、和や条件を満たす組み合わせの個数・最大値
  • N 人をチーム A / B に分ける最良の分け方 (2^N 通りの分け方)
  • N 個のスイッチ / 電球の ON・OFF のすべての状態を試す
  • N ≤ 8 の並び替えで最短経路や最良の順序を求める (順列全探索)
