ダイクストラ法

辺に非負の重みがある最短路。BFS の「近い順に確定」を、キューの代わりに優先度付きキュー (距離が小さいものから出てくる) で行います。取り出した頂点の距離はその時点で確定なので、そこから隣を更新 (緩和) していくだけです。

考え方

確定の順番　未確定の中で最も距離が小さい頂点は、他のどの経路でもそれより短くならない (重みが非負だから)。だから取り出した瞬間に確定してよい。優先度付きキューには (距離, 頂点) を入れ、取り出したときに「古い情報」(dist より大きい) なら捨てる。
  • 負の辺があると成り立たない → ベルマンフォード or ワーシャルフロイド。
  • 「古い情報を捨てる」チェックを忘れると計算量が壊れる (同じ頂点を何度も広げる)。
  • 頂点数 N ≤ 10^5, 辺数 M ≤ 2×10^5 の制約はダイクストラのサイン。
  • 経路復元は、更新したときに prev[u] = v を記録して終点から逆にたどる。

動かして見る

頂点 0 から各頂点への最短距離。緑が確定、黄色が優先度付きキューに入っている頂点です。

実装

計算量とハマりどころ

  • O((N + M) log N)。N = M = 2×10^5 で 10^7 程度。
  • C++ の priority_queue は既定で大きい順。greater<P> を忘れない。pair の順序は (距離, 頂点) で距離を先に。
  • 距離の合計は int を超えやすい。long long と INF = 10^18。
  • 無向グラフは両方向に辺を入れる。
  • 「状態」を頂点に: (頂点, 使った割引券の枚数) のように N × K 個の頂点で回すと、条件付き最短路になる。
  • 全点対 (N ≤ 400 程度) はワーシャルフロイド O(N^3) の方が楽。

典型問題のパターン

  • 都市間の最短時間、最小コスト (辺の重みが非負)
  • 「電車は乗り換えに時間がかかる」など、辺の重みが状態に依存する最短路
  • 始点が複数あるとき: すべて距離 0 でキューに入れる (多始点ダイクストラ)
  • 「通ってよい頂点を 1 つだけ追加できる」→ 始点からと終点からの 2 回のダイクストラを合わせる
