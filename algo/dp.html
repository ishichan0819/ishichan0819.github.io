動的計画法 (DP)

「全探索したいが 2^N は無理」なとき、途中までの結果を表にして使い回すのが DP です。緑から水色に上がる最大の壁で、コツは「表の定義を日本語で 1 文で言えるまで決める」こと。ここでは 0-1 ナップサックで表の埋まり方を見ます。

考え方

dp[i][w] = 最初の i 個の品物から、重さの合計が w 以下になるように選んだときの価値の最大値　品物 i (重さ W_i, 価値 V_i) を「選ばない」なら dp[i][w] = dp[i−1][w]、「選ぶ」なら dp[i−1][w − W_i] + V_i。大きい方を取る。答えは dp[N][W]。
  • 手順: ① 表の定義 ② 初期値 (dp[0][*] = 0) ③ 遷移 (どこから来るか) ④ 答えの場所 ⑤ 計算順 (依存先が先に埋まる順)。
  • 「もらう DP」(dp[i] を作るために前を見る) と「配る DP」(dp[i] から先へ足す) は同じことの裏表。書きやすい方で。
  • ナップサックは重さを添字にしたが、価値が小さく重さが巨大なら「価値を添字にして重さの最小値を持つ」と入れ替える。
  • LIS (最長増加部分列)、編集距離、区間 DP、bit DP、木 DP はすべて「表の定義」を変えただけ。

動かして見る

品物 4 個、容量 W = 8。表の各マスが上の行のどこから来たかを水色で示します。

実装

計算量とハマりどころ

  • ナップサックは O(NW)。N = 100, W = 10^5 なら 10^7 で余裕。W = 10^9 なら価値側を添字にする。
  • 初期値: 最大化なら 0 か −∞、最小化なら +∞ (1e18)。「到達不能」を表す値を決めておく。
  • 1 次元化するときのループの向き (0-1 は逆順、無制限は正順) を混同しない。
  • 「i 番目まで見た」の i が 0-indexed か 1-indexed かを固定する。dp のサイズは N+1。
  • 復元が必要なら、どの遷移を選んだかを別の表に残すか、答えから逆にたどる。
  • メモ化再帰でも同じ。C++ なら再帰でも速いが、Python では表を回す方が安全。

典型問題のパターン

  • ナップサック (0-1 / 個数無制限 / 個数制限あり)、部分和が作れるか (bool の DP)
  • 最長増加部分列 (LIS)、最長共通部分列 (LCS)、編集距離
  • 階段の上り方の数、経路の数 (mod 10^9+7 で数える DP)
  • 「i 日目にどの行動をとるか」で状態を持つ (dp[i][行動])
  • 区間 DP (dp[l][r]: 区間 [l, r) の最適値)、bit DP (dp[集合][最後の頂点])
