貪欲法とソート

「その時点で一番よさそうな選択」を繰り返すのが貪欲法です。うまくいく問題では圧倒的に速く簡単ですが、なぜ正しいかを言えないと、うまくいかない問題で使ってしまいます。ここでは代表例の区間スケジューリングで、正しい理由まで確かめます。

考え方

区間スケジューリング　重ならないように最大何個の区間を選べるか。答え: 終わりが早い順に見て、直前に選んだ区間と重ならなければ選ぶ。理由 (交換論法): 最適解の最初の区間を「終わりが最も早い区間」に置き換えても、残りの選択肢は減らない。以下同様。
  • 貪欲が正しい典型的な形: ソートして端から決める / 交換しても損しないことが示せる / マトロイド構造がある。
  • 正しさが言えないときは、小さいケースで全探索と比べる (反例探し)。
  • 「終わりが早い順」ではなく「始まりが早い順」や「短い順」だと反例がある (図で試せます)。
  • ソートの比較関数を自分で書く (sort(v.begin(), v.end(), [](auto& a, auto& b){ return a.second < b.second; }))。

動かして見る

区間を終了時刻でソートし、左から見ていきます。黄色が今見ている区間、緑が採用、薄い赤が却下です。

実装

計算量とハマりどころ

  • ソート O(N log N) + 1 回の走査 O(N)。
  • 「端が接する」を許すかで >= か > が変わる。問題文を読む。
  • 「見た目が貪欲っぽい」問題の多くは DP。貪欲で WA が出たら DP を疑う。
  • ソートの key に複数条件 (第 1 キー、第 2 キー) が必要なことが多い。tuple にして sort。
  • priority_queue と組み合わせる貪欲 (「今取れる中で最大を取る」) は頻出。

典型問題のパターン

  • 区間スケジューリング、会議室が何部屋必要か (開始・終了イベントをソート)
  • ロープや紙を切るコストの最小化 (小さい順に合体)
  • マッチング: 「A の各要素に B の要素を割り当てて条件を満たす」を両方ソートして 2 ポインタ
  • 文字列を辞書順最小にする操作 (先頭から貪欲に小さい文字を置く)
  • 締め切りと報酬のある仕事の選択 (締め切り順 + ヒープ)
