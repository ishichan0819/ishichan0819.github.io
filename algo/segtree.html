セグメント木

「1 点を更新」と「区間の和 / 最小 / 最大を取得」をどちらも O(log N) でこなすデータ構造です。累積和は更新に弱く、配列は取得に弱い。その両方を、区間を半分ずつに分けた木で解決します。水色から青に上がるとき、N = 2×10^5 のクエリ問題で必ず使います。

考え方

1-indexed の配列で木を持つ　葉を n 個 (n は N 以上の 2 のべき) 用意し、葉 i は tree[n + i]。親は k / 2、子は 2k, 2k+1。根 tree[1] が全体の値。ノード k は「自分の担当区間」の演算結果を持つ。
  • 更新: 葉を書き換え、親へ上がりながら tree[k] = op(tree[2k], tree[2k+1]) で作り直す。log N 個。
  • 取得 [l, r): 左右から狭めていく (ボトムアップ)。l が右の子なら取って右へ、r が右の子なら 1 つ戻って取る。担当区間がぴったり収まるノードだけを O(log N) 個集める。
  • 演算は結合法則があればよい: 和、最小、最大、gcd、XOR、行列積… 単位元 (和なら 0、最小なら +∞) を決める。
  • 「区間に一様に足して区間の和」は遅延評価セグメント木 (青以降)。

動かして見る

N = 8 の区間和セグメント木。まず 1 点更新で親が作り直される様子、次に区間 [2, 7) の和をどのノードから集めるかを見ます。

実装

計算量とハマりどころ

  • 更新・取得ともに O(log N)。メモリは 2n (n は N 以上の 2 のべき) で最大 4N。
  • 単位元を間違えると最小値クエリが 0 を返したりする。min なら +∞、max なら −∞、gcd なら 0。
  • 取得は半開区間 [l, r)。閉区間で聞かれたら r+1。
  • 非可換な演算 (行列積など) は左右の順序を保つ。上のコードは L と R を分けているので対応済み。
  • Python は素直に書くと遅い。PyPy を使うか、ループを関数の外で回さない。
  • C++ なら AtCoder Library の atcoder::segtree をそのまま使ってよい。

典型問題のパターン

  • 点更新と区間和 / 区間最小 / 区間最大のクエリが混ざる
  • 転倒数 (右から見て「自分より小さい値が何個あるか」を出現回数のセグ木で)
  • 「x 以下の要素の個数」を座標圧縮 + セグ木 (または BIT)
  • LIS の変形: 「末尾が v 以下の最長増加列」を最大値セグ木で
  • 区間の最大値を持ち、二分探索で「左から初めて x 以上になる位置」を探す (max_right)
