Union-Find

「a と b を同じグループにする」「a と b は同じグループか?」を何度も処理するデータ構造です。各要素が親を 1 つ持つ森として表し、根が同じなら同じグループ。経路圧縮と union by size を入れると、1 回の操作がほぼ O(1) になります。

考え方

find(x) = x の根。たどる途中の頂点を全部根に直接つなぎ直す (経路圧縮)。unite(a, b) = 根どうしをつなぐ。小さい木を大きい木の下につける (union by size)。同じグループかは find(a) == find(b)。
  • 辺を追加していく問題 (時間順に「つながる」) と相性がよい。逆に辺を削除する問題は、クエリを逆順にして「追加」に変える。
  • グループのサイズを根に持たせると「グループの人数」も O(1)。
  • 「連結成分の数」は N から unite が成功した回数を引くだけ。
  • 重み付き Union-Find (a と b の差が d) や、2 部グラフ判定への拡張もある。

動かして見る

8 個の要素に unite を順に適用します。矢印は「親」を指します。

実装

計算量とハマりどころ

  • 経路圧縮 + union by size で 1 操作あたり実質 O(α(N)) ≈ O(1)。片方だけでも O(log N)。
  • 「グループの大きさ」「グループの数」は根でしか正しくない。必ず find してから見る。
  • unite の戻り値 (新しくつながったか) を数えると「何本目の辺で全部つながるか」が分かる。
  • Python は再帰版 find だと深い木で RecursionError。上のループ版を使う。
  • 頂点番号は 0-indexed に揃える。1-indexed 入力は −1。

典型問題のパターン

  • 辺を 1 本ずつ追加して、追加のたびに連結成分の数 / 最大グループの大きさを答える
  • 「道が壊れる」順を逆にして、つながっていないペア数の変化を求める
  • クラスカル法 (最小全域木): 辺を重み順に見て、別グループなら採用
  • グリッドで同じ色のマスをつなぎ、領域の数を数える
  • 「x と y は同じ人 (別名)」のようなグループ判定
