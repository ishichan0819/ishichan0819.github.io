FPGA で色を送る

「色で文字を送る」では DCSK の考え方を見ました。このページでは、それを実際に FPGA で作った回路を動かします。どれも Zybo と Eclypse Z7 というボード用に Verilog で書いた、実物のプログラムです。ブラウザの中の仮想ボードで、クロック1回ずつから実際の速さまで動かせます。

① 仮想ボードで動かす

プログラムを選んで ▶ を押してください。回路は、大きく3つの部品でできています。

  • 分周カウンタ: 125MHz のクロックを数えて、ときどき「進め」の合図 ledcnten を出す
  • LFSR: その合図で次の乱数に進む
  • 色の表: 乱数の下の数ビット n で、点ける LED を選ぶ

③ 受信して誤りを数える


① で選んでいるプログラムの光を、赤・緑・青のフィルタを付けた3つの受光素子で受けます。各シンボルの最後に強さを測り、色の表でいちばん近い色を選びます。受信側も同じ LFSR を持っているので、「送られたはずのシンボル」と比べて誤りを数えられます。乱数の列を通信の試験に使うのは、このためです。

見えたこと

    
  
  • 速さは分周カウンタのビット数で決まる。b ビットなら 2b クロックに1回だけ合図が出るので、1シンボルは 2b ÷ 125MHz。20ビットで約 8.4ms、10ビットで約 8.2µs。
    • 
  
  • 乱数は LFSR で作れる。シフトと XOR だけの回路で、0 以外の 511 通りを全部めぐる。ただし全ビット 0 から始めると、0 のまま止まる (RGB_random)。blue_chika のように初期値を書くか、RST で 1 を入れる。
    • 
  
  • DCSK は表を引くだけ。n で 9ビットのパターンを選ぶだけなので、アナログの調光がいらない。点いている LED の数が同じなら、明るさも変わらない。
    • 
  
  • 速すぎると受信側が追いつかない。受光素子が遅いと前のシンボルの光が残り、隣の色と混ざって化ける。速い素子は雑音も多く拾うので、距離を縮めるなどして光を強くする必要がある。
    • 
  
  • ゆっくりだと目に見える。1秒に100回くらいより遅いと、色の切り替わりがちらついて見えやすい (目安)。速くすると混ざって白っぽく見える。
    • 





    
  
  • 回路は各フォルダの Verilog (LED.v / rgb.v) をそのまま動かしています。ヘッダのコメントと、コメントアウトされた行は表示から省いています。空のテンプレート (project_2) と、スイッチをそのまま LED に出すだけのもの (project_1) は載せていません。
    • 
  
  • クロックはどのボードも 125MHz として計算しています。ピン番号は各プロジェクトの制約ファイル (.xdc) のとおりです。
    • 
  
  • LED 9個の色は、信号点を確かめる版 (singoutenn の red / green / blue) から読み取りました。[2:0] が赤、[5:3] が緑、[8:6] が青です。RGB LED 1個のプログラムでは、出力の [2] [1] [0] を R・G・B として表示しています。実際の色の順は配線によります。
    • 
  
  • RST ボタンのあるプログラムは、RST を押した直後の状態から始めます。
    • 
  
  • 受信側は説明用のモデルです。受光素子は1次の低域フィルタとし、雑音は帯域の平方根と外光に比例させています。距離による減衰は分かっているものとし、シンボルの区切りも正しく分かるものとしています。実際の測定値は使っていません。
