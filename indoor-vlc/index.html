部屋じゅうに光を届ける

前の2ページでは、LEDと受光器がまっすぐ向かい合っていました。実際の可視光通信では、天井の照明が部屋を照らしながら、机の上のあちこちにある受信機(スマホやPC)へデータを届けます。照明として十分に明るい場所なら、通信もできるのでしょうか? 5m × 5m × 天井3m の部屋を上から見た地図で確かめます。

① 照明の地図と、通信の地図

天井のLED照明(●)をドラッグで動かし、地図をクリックして受信機(■)を置いてください。地図の上の切り替えで、机の高さ(0.85m)での照度(照明としての明るさ)とSNR(通信としての信号の強さ)を見比べます。赤い斜線は、照明なら暗すぎ・まぶしすぎ、通信なら誤りが多すぎる場所です。

② 壁の反射が速さを決める

光は壁でも跳ね返ります。反射光は遠回りするぶん遅れて届き、前のビットの光が次のビットに重なります(符号間干渉)。受信機に届く光を時間順に並べたのが右のグラフ(インパルス応答)。遅れの広がり Drms が大きいほど速く送れず、上限の目安は 1/(10·Drms) です。地図は場所ごとの「速さの上限」です。

③ 人が立つと影ができる

光は人の体を通り抜けません。人をドラッグして、受信機とLEDの間に入れてみてください。すべてのLEDが同じデータを送る放送型と、LEDごとに別の受信機へ送るセル型を切り替えられます。セル型では受信機はいちばん強く届くLEDにつなぎ、ほかのLEDの光は干渉(じゃま)になります。

見えたこと

  • 照明の明るさと通信の届き方は別もの。照度は机に届く光の量で決まるが、通信は受信機の視野(FOV)に入ったLEDの光しか使えない。
  • 視野角はトレードオフ。狭めるとレンズで光を集められて信号は強くなり、反射も拾いにくくなる。そのかわり、どのLEDも見えない死角ができる。
  • 光の量は十分でも、速さは反射で頭打ちになる。遠回りした光が遅れて届き、部屋の隅や壁ぎわほど遅れの広がりが大きい。
  • 影には複数のLEDで備える。1灯だと人の影でリンクが切れるが、放送型で同じデータを送る複数灯なら別のLEDが補う。
  • セル型は干渉との戦い。LEDごとに別のデータを送れば部屋全体で運べる量は増えるが、光が重なる境目では通信できない。受信機が境目をまたぐと、つなぎ先が切り替わる(ハンドオーバー)。

計算に使った式とパラメータ

Komine & Nakagawa (2004) の室内モデルに沿って計算しています。LEDは天井(高さ3m)で真下向き、受信機は机の高さ0.85m。

LEDの配光(ランバート放射)

m = −ln 2 / ln(cos Φ½)　　(Φ½: 半値角)

照度(机の上、水平面)

E = Σ I(0) cosmφ · cos ψ / d²

直接光のチャネル利得(視野の中だけ)

H(0) = (m+1)A / (2πd²) · cosmφ · Ts · g(ψ) · cos ψ,　g(ψ) = n² / sin²Ψc　(0 ≤ ψ ≤ Ψc)

壁での1回反射(②)

dH = (m+1)A / (2π² d1² d2²) · ρ dAw · cosmφ · cos α · cos β · Ts · g(ψ) · cos ψ,　遅れ t = (d1+d2) / c

壁を 0.25m 角(地図)/ 0.05m 角(受信機の点)に分割。天井・床の反射と2回以上の反射は入れていません。

SNR と誤り率(OOK)

SNR = (γPr)² / (σ²shot + σ²thermal),　BER = Q(√SNR)
σ²shot = 2qγPrB + 2qIbgI2B
σ²thermal = (8πkTk/G) ηA I2B² + (16π²kTkΓ/gm) η²A² I3B³

BER ≤ 10⁻⁶ になるのは SNR ≥ 13.5 dB。これを「通信できる」の基準にしています。

遅延広がり(②)

τ̄ = Σ tihi / Σ hi,　Drms = √( Σ (ti − τ̄)² hi / Σ hi ),　速さの上限の目安 R ≈ 1 / (10·Drms)

セル型の SINR(③)

SINR = (γPs)² / (σ²shot + σ²thermal + (γ Σi≠s Pi)²)　(Ps: いちばん強いLED)
